This page is the **canonical guide** for product versioning and redline (comparison) review in Uprevit. Other documentation pages link here instead of repeating the full workflow.

The lifecycle is: **Draft → Submitted → In Review → Released → Obsolete**. An [approval workflow](/docs/review-outputs/approval-workflows) is the only way a version becomes Released. To change a Released version, create a new version.

## Concepts

| Term | Meaning |
|------|---------|
| **Version** | Numeric revision on a product (`v1`, `v2`, …). All versions of a product share one lineage. |
| **Draft** | Editable; new products and new versions start here. |
| **Submitted** | Ready for an approval workflow. Still editable. |
| **In Review** | Inside an active approval workflow. Still editable; approvers get a change notice when reviewed content changes. |
| **Released** | Approved through a workflow. All seven tabs are read-only. |
| **Obsolete** | An earlier release replaced by a newer one. Read-only history. |
| **Redline / compare** | Read-only diff of an older version against the version you are viewing. |
| **Tab completion** | Each of the seven tabs can be marked complete; **100%** (7/7) is required to submit. |

## Tab completion and submit

1. Open each product tab and enter data.
2. When a tab is finished, hover the progress in the product header and click **Mark Complete**.
3. When progress shows **100%**, **Submit for approval** becomes available.
4. Confirm in the submit dialog.

Submit:

- Sets status to **Submitted**
- Records **actual completion date** (today)
- Keeps the version editable. While it is Submitted, you can **Return to draft**. If someone else returns your version to Draft, you're notified.

While a version is Submitted or In Review, completed tabs can't be marked incomplete.

The version is released when an [approval workflow](/docs/review-outputs/approval-workflows) that includes it completes. Any earlier release of the product becomes **Obsolete**.

## Creating a new version

After release, continue work by branching a new draft:

1. On `/products`, open the row menu for a **Released** product.
2. Choose **New version**, then confirm **Create Version N**.
3. Uprevit copies the data and the product team into a new version: **Draft** status, incremented version, all tabs incomplete, and no target or completion date.
4. You are navigated to the new version’s **Product Information** tab.

Only the latest version, when it is **Released**, can spawn a new version. While the new version is being worked on, the product header shows a **Released vN** link to the current release.

## Switching versions

Use the version menu in the product header to jump between versions of the same product. Each version shows its status, its release or obsolete date, and the workflow that released it. When a newer version is being worked on, **Released vN** next to the menu opens the current release. The current tab path is preserved (e.g. stay on Label Components when switching from v1 to v2).

## Compare versions (redline)

Redline is for **reviewing what changed** between an older version and the version open in the URL.

### Start comparison

1. Open any product tab for the **newer** version you want as the “current” side.
2. In the header, click **Compare**.
3. Select an older version (only versions with a lower version number appear).

### While comparing

- A **Redline View** banner shows the number of changes on the tab.
- **Product Specifications** and **Operational Parameters** offer **Highlight** vs **Inline** diff modes on the grid.
- **Label Tags** shows OLD and NEW images side by side.
- Tables mark added, removed, and changed rows with **NEW**, **DEL**, and **MOD** badges.
- The comparison stays on when you switch to another product tab, so you can review the whole product without selecting the version again.

### End comparison

Click **Clear comparison** in the header. The page returns to normal edit or read-only mode based on status.

Comparing never changes either version's data.

## Edit locks

| Condition | Effect |
|-----------|--------|
| **Released** or **Obsolete** | No tab edits. |
| **Not on the product team** | Only the Product Owner, Contributors, and admins can edit. |
| **Your PDF export in progress** | The product shows **Export in progress** and can't be edited until the export finishes. |

## Where redline appears

All seven documentation tabs participate. Product tab docs describe tab-specific fields and link here for compare workflow.

## Product logs

Admins can click **Logs** on **Product Information** to see who changed the product and when. Use it alongside redline when you need timestamps and people, not field-level diffs.
